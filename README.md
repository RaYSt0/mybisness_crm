# МойБизнес CRM

Учебный frontend CRM для школы танцев, спортивной секции или учебного центра. Владелец просматривает учеников, посещения и платежи, выбирает модули рабочего пространства и знакомится с правами сотрудников.

## Лабораторная №1

Реализован интерфейс и каркас frontend. Используются демонстрационные данные: сервер, вход в систему и реальные операции с платежами пока отсутствуют. По методичке backend следующих этапов должен использовать Python + FastAPI, PostgreSQL + SQLAlchemy.

### Экраны и пользовательские сценарии

| Адрес | Экран | Сценарий |
| --- | --- | --- |
| `/` | Главная | Просмотреть уведомления и графики, перейти к ученику или финансам |
| `/students` | Ученики | Найти ученика по имени или группе, открыть карточку; обработать пустой результат |
| `/students/1` | Карточка ученика | Переключить информацию, посещения, платежи и документы; вернуться к списку |
| `/constructor` | Конструктор CRM | Выбрать тип бизнеса, включить модули, проверить итог на третьем шаге |
| `/finance` | Финансы | Просмотреть демонстрационные платежи; при выключенном модуле перейти к настройке |
| `/settings` | Команда и права | Выбрать сотрудника и просмотреть права его роли и общую матрицу |
| `/help` | Помощь | Ознакомиться с порядком работы и ограничениями прототипа |
| Любой неизвестный адрес | Страница не найдена | Вернуться на главную |

Навигация реализована через React Router (`BrowserRouter`, `Routes`, `NavLink`, `Link`). Работают прямые адреса, обновление страницы и история браузера. На хостинге для адресов приложения нужно настроить возврат `index.html` (SPA fallback).

## Технологии и структура

- React 18 + TypeScript, Vite 6.
- UI: shadcn/ui на Radix UI; `Button`, `Input`, `Card`, `Switch` используются в интерфейсе. Общее оформление — Tailwind CSS 4 и CSS-переменные темы.
- Recharts для демонстрационной аналитики, Lucide для иконок.
- Playwright для проверки сценариев и сохранения скриншотов.

```text
src/app/components/layout/  — шапка и навигация
src/app/components/views/   — экраны приложения
src/app/components/ui/      — готовые UI-компоненты
src/app/config/             — типы, пресеты, модули, матрица ролей
src/app/state/              — состояние конфигурации и localStorage
src/styles/                 — тема, Tailwind и адаптивная раскладка
tests/                      — браузерные проверки
docs/screenshots/           — скриншоты экранов
```

## Установка и запуск

Требуются Node.js 22 LTS и npm. Секреты и переменные окружения для frontend не нужны.

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://localhost:5173).

```bash
npm run typecheck
npm run build
npm run preview
```

`build` сначала проверяет TypeScript, затем создаёт `dist/`. `preview` позволяет проверить эту сборку локально.

## Проверка интерфейса и обновление скриншотов

```bash
npx playwright install chromium
npm run test:e2e
```

Тесты сами запускают Vite на порту 4173. Проверяются прямые адреса, отсутствие горизонтального переполнения на ширинах 1440 и 390 px, поиск и пустой результат, переходы назад/вперёд, вкладки профиля, сохранение пресета и модулей после перезагрузки, выключенный финансовый модуль, просмотр прав, повреждённое и недоступное хранилище браузера. Скриншоты обновляются в `docs/screenshots/`; после изменений интерфейса их нужно просмотреть и сохранить вместе с кодом в Git.

В среде первоначальной проверки Chromium установлен во временную папку; команда проверки здесь: `PLAYWRIGHT_BROWSERS_PATH=/tmp/crm-playwright npm run test:e2e`. Для обычной установки используйте команды выше.

## Изменения при подготовке к лабораторной

- Переключение экранов через `useState` заменено клиентской маршрутизацией для прямых ссылок и истории браузера.
- Добавлены список учеников, финансы, помощь и неизвестный адрес: ранее пункты «Финансы» и «Помощь» показывали главную.
- Добавлены готовые UI-компоненты, мобильная навигация, перенос блоков и прокрутка широких таблиц и вкладок.
- Неработающий глобальный поиск и быстрые действия убраны; поиск доступен в списке учеников. Недоступные серверные операции помечены как демо или отключены, чтобы не создавать ложного ожидания сохранения.
- Исправлено чтение конфигурации до первого сохранения; недоступное или повреждённое хранилище не мешает работе интерфейса.
- Добавлены строгая проверка TypeScript, браузерные тесты и `.gitignore`.

## Ограничения и сдача

Данные главной и карточки — отдельные примеры, а не согласованная база CRM. В списке доступен один демонстрационный ученик. Настройки модулей сохраняются только в текущем браузере; при запрете хранилища — до обновления страницы. Матрица ролей не является серверной авторизацией. Создание сотрудников, удаление, документы и реальные платежи требуют следующих этапов.

Подробное сравнение исходного проекта с заданием: [docs/lab-1-audit.md](docs/lab-1-audit.md).

Тему и платформу репозитория нужно согласовать с преподавателем. Перед сдачей разместите Git-репозиторий на согласованной платформе и предоставьте преподавателю доступ. Продолжайте делать осмысленные коммиты: первый коммит текущего проекта не восстанавливает историю старой разработки.

Общие требования методички запрещают ИИ-генерацию кода, включая фрагменты. При подготовке этой версии использовалась ИИ-помощь; соответствие этому организационному условию не заявляется.
