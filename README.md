# FlowBiz — рабочее пространство для малого бизнеса

## Структура проекта

```text
frontend/   React-приложение, его тесты, конфигурация и документация
backend/    FastAPI API, SQLAlchemy-модели, схемы, сервисы и тесты
docker-compose.yml  PostgreSQL для backend
```

## Frontend часть

FlowBiz помогает небольшому бизнесу собрать клиентов и ежедневные процессы в рабочем пространстве, составленном под выбранное направление. Система предлагает сущности, процессы и напоминания, а владелец настраивает их перед запуском. Frontend: React, TypeScript и Vite. Backend: FastAPI и PostgreSQL.

## Запуск

Требуются Node.js 22 LTS, Python 3.12 и Docker Desktop (для PostgreSQL).

```bash
docker compose up -d db
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload --port 8001
```

В другом терминале из корня проекта запустите frontend:

```bash
cd frontend
npm ci
npm run dev
```

`frontend/.env.example` задаёт API `http://localhost:8001/api/v1`. Если сервер недоступен, интерфейс продолжает работать на localStorage и показывает статус демо-режима. Подробные команды приведены в [backend/README.md](backend/README.md).

Откройте адрес Vite в терминале (обычно http://localhost:5173).

```bash
npm run typecheck
npm run build
npm run preview
```

Сборка сначала проверяет TypeScript и создаёт `frontend/dist/`. Для публикации на хостинге нужен SPA fallback на `index.html`, чтобы прямые адреса страниц открывались корректно.

## Экраны и сценарии

| Адрес | Экран и сценарий |
| --- | --- |
| `/register` | Демо-регистрация владельца и бизнеса |
| `/onboarding` | Выбор категории и описание бизнес-процессов |
| `/configure` | Подтверждение предложенных сущностей, процессов и автоматизаций |
| `/ready` | Создание рабочего пространства и сохранение конфигурации |
| `/` | Dashboard; при подключённом API показатель клиентов рассчитывается на сервере |
| `/clients`, `/clients/:id` | Список клиентов, поиск, добавление и карточка |
| `/schedule`, `/groups`, `/team`, `/payments`, `/documents`, `/tasks` | Операционные разделы с демонстрационными данными |
| `/automations`, `/reports`, `/settings` | Правила, показатели и настройка конфигурации |

При первом запуске открывается регистрация. После подтверждения конфигурации frontend создаёт организацию и сохраняет её настройки через FastAPI. Клиенты хранятся в таблице `clients`; `/dashboard-summary` агрегирует их статусы для dashboard. Локальное хранилище держит черновик интерфейса и позволяет продолжить работу в демо-режиме. Регистрация учебная: настоящей аутентификации нет, пароль не отправляется и не хранится.

## Стек и структура

React 18, TypeScript, Vite 6, React Router 7, Tailwind CSS 4. Используются компоненты shadcn/ui на Radix UI (`Button`, `Input`, `Card`, `Switch`), Recharts и Lucide.

```text
frontend/
  src/
  main.tsx                    точка входа React
  app/
    App.tsx                   маршруты и общий каркас
    components/
      layout/                 шапка и боковая навигация
      views/                  отдельные экраны
      ui/                     5 используемых файлов UI и утилит
    product/                  модели FlowBiz, шаблоны, mock и HTTP API service
    state/                    состояние рабочего пространства
  styles/                     тема, Tailwind, адаптивная раскладка
  tests/                      сценарные проверки Playwright
  docs/
    defense.md                подготовка к защите и ответы на вопросы
    screenshots/              актуальные скриншоты экранов
```

`WorkspaceProvider` управляет onboarding и данными. UI вызывает service слой, который использует FastAPI, когда `VITE_API_URL` настроен, и localStorage/mock данные при недоступном сервере. Backend разделяет работу по HTTP-маршрутам, Pydantic-схемам, сервисам, репозиториям и SQLAlchemy-моделям.

## Проверки и скриншоты

```bash
cd frontend
npx playwright install chromium
npm run test:e2e
```

Тесты запускают Vite на порту 4173 и проверяют onboarding, конфигурацию, работу workspace, задачи, автоматизации, API fallback и мобильную ширину. Backend тесты проверяют CRUD, валидацию, tenant-scope, хранение версии конфигурации и серверную сводку клиентов.

В текущей рабочей среде браузер установлен во временную папку: `PLAYWRIGHT_BROWSERS_PATH=/tmp/crm-playwright npm run test:e2e`. При обычной установке используйте команды выше.

## Что очищено и изменено

- Удалены 43 неиспользуемых UI-файла, компонент изображений Figma, пустые настройки PostCSS/pnpm, пустой файл шрифтов, дублирующая тема и шаблон guidelines.
- Удалена устаревшая отдельная заметка README_AI; актуальная архитектура, ограничения и дальнейший стек описаны здесь.
- Оставлены 10 прямых зависимостей приложения; React и React DOM объявлены обычными зависимостями приложения. Неиспользуемые MUI, карусели, drag-and-drop и прочие пакеты удалены.
- Удалён неиспользуемый Figma resolver из Vite. Экраны списка, формы, финансов и помощи разнесены по отдельным файлам.
- Вместо единственной жёстко заданной карточки добавлены связанные сценарии работы с учениками. Персональная информация теперь берётся из модели Student.
- Настроена мобильная раскладка, широкие таблицы и вкладки прокручиваются внутри блоков. Скриншоты обновлены после функциональных изменений.

`node_modules/` нужен для локального запуска, `dist/` создаётся сборкой, `test-results/` — тестами. Эти каталоги исключены из Git и могут быть восстановлены командами npm. Скриншоты и тесты оставлены как материалы лабораторной.

## Ограничения и следующие этапы

Клиенты, конфигурация и сводка dashboard подключаются к PostgreSQL через API. Расписание, платежи, графики, документы, задачи и сотрудники пока демонстрационные. Авторизация и роли не реализованы: `organization_id` в маршруте не является production-защитой. Локальная копия workspace сохраняется в браузере.

Backend для лабораторной №3 находится в `backend/`. Полный сценарий и объяснение защиты приведены в [docs/LAB3_DEFENSE.md](docs/LAB3_DEFENSE.md).

Следующие этапы: добавить аутентификацию и права доступа, затем постепенно подключить расписание, платежи, документы и автоматизации.

При доработке использовалась ИИ-помощь. Методичка запрещает ИИ-генерацию кода; соответствие этому организационному условию не заявляется. Памятка [для защиты](frontend/docs/defense.md) помогает разобраться в реализации, а не скрывать происхождение кода.
