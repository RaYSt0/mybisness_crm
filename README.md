# МойБизнес CRM

## Frontend часть

Учебный frontend для школы танцев, спортивной секции или учебного центра. После демонстрационной регистрации владелец создаёт персональное рабочее пространство: задаёт название бизнеса, тип и состав модулей. Затем ведёт список учеников и открывает их карточки. Проект подготовлен для лабораторной №1: интерфейс, маршрутизация, UI-библиотека, базовая адаптивность и демонстрационные данные.

## Запуск

Требуются Node.js 22 LTS и npm. Переменные окружения, сервер и база данных для этой версии не нужны.

```bash
npm ci
npm run dev
```

Откройте адрес Vite в терминале (обычно http://localhost:5173).

```bash
npm run typecheck
npm run build
npm run preview
```

Сборка сначала проверяет TypeScript и создаёт `dist/`. Для публикации на хостинге нужен SPA fallback на `index.html`, чтобы прямые адреса страниц открывались корректно.

## Экраны и сценарии

| Адрес | Экран и сценарий |
| --- | --- |
| `/onboarding` | Регистрация владельца и создание персональной CRM: название бизнеса, пресет и модули |
| `/` | Главная: число активных учеников и групп, демонстрационные уведомления и графики |
| `/students` | Поиск по имени/группе, фильтр активных и архивных учеников |
| `/students/new` | Создание ученика с проверкой обязательных полей, email и даты рождения |
| `/students/:studentId` | Карточка конкретного ученика, вкладки, архивирование и восстановление |
| `/students/:studentId/edit` | Редактирование данных с сохранением идентификатора |
| `/constructor` | Повторная настройка типа бизнеса и модулей через «Настройки» |
| `/finance` | Пример истории платежей; при выключенном модуле — переход к конструктору |
| `/settings` | Демонстрационный список сотрудников и просмотр прав ролей |
| `/help` | Порядок работы и ограничения |
| Неизвестный адрес / ID | Страница не найдена / ученик не найден с возвратом к списку |

При первом запуске приложение перенаправляет на `/onboarding`: до завершения анкеты нельзя открыть рабочие страницы. Имя владельца, email, название бизнеса, тип и модули сохраняются в `localStorage`, а название применяется в интерфейсе. Регистрация учебная: аккаунт не отправляется на сервер и существует только в текущем браузере. Архивирование учеников обратимо: карточка остаётся в системе и доступна через фильтр «В архиве». Новые ученики не получают чужую демонстрационную историю платежей или посещений. Если сохранение недоступно, приложение сообщает об этом: изменения останутся в памяти до перезагрузки.

## Стек и структура

React 18, TypeScript, Vite 6, React Router 7, Tailwind CSS 4. Используются компоненты shadcn/ui на Radix UI (`Button`, `Input`, `Card`, `Switch`), Recharts и Lucide.

```text
src/
  main.tsx                    точка входа React
  app/
    App.tsx                   маршруты и общий каркас
    components/
      layout/                 шапка и боковая навигация
      views/                  отдельные экраны
      ui/                     5 используемых файлов UI и утилит
    config/                   типы бизнеса, модули и матрица ролей
    data/                     модель Student и демонстрационные данные
    state/                    общее состояние учеников и бизнес-настроек
  styles/                     тема, Tailwind, адаптивная раскладка
tests/                        сценарные проверки Playwright
docs/
  defense.md                  подготовка к защите и ответы на вопросы
  screenshots/                актуальные скриншоты экранов
```

`StudentsProvider` хранит единый список учеников. Список, карточка и главная читают его через `useStudents`. При сохранении обновляются состояние React и JSON в браузере. `useBusinessConfig` независимо хранит конфигурацию модулей. Записи из браузера проверяются во время загрузки: TypeScript сам по себе не проверяет JSON во время выполнения.

## Проверки и скриншоты

```bash
npx playwright install chromium
npm run test:e2e
```

Тесты сами запускают Vite на порту 4173. Покрыты прямые адреса, история браузера, ширины 1440 и 390 px, поиск, вкладки, конфигурация, создание/редактирование/архив/восстановление ученика, валидация и ошибки хранилища. Скриншоты обновляются в `docs/screenshots/`; после изменения UI просмотрите их и сохраните в Git вместе с исходниками.

В текущей рабочей среде браузер установлен во временную папку: `PLAYWRIGHT_BROWSERS_PATH=/tmp/crm-playwright npm run test:e2e`. При обычной установке используйте команды выше.

## Что очищено и изменено

- Удалены 43 неиспользуемых UI-файла, компонент изображений Figma, пустые настройки PostCSS/pnpm, пустой файл шрифтов, дублирующая тема и шаблон guidelines.
- Удалена устаревшая отдельная заметка README_AI; актуальная архитектура, ограничения и дальнейший стек описаны здесь.
- Оставлены 10 прямых зависимостей приложения; React и React DOM объявлены обычными зависимостями приложения. Неиспользуемые MUI, карусели, drag-and-drop и прочие пакеты удалены.
- Удалён неиспользуемый Figma resolver из Vite. Экраны списка, формы, финансов и помощи разнесены по отдельным файлам.
- Вместо единственной жёстко заданной карточки добавлены связанные сценарии работы с учениками. Персональная информация теперь берётся из модели Student.
- Настроена мобильная раскладка, широкие таблицы и вкладки прокручиваются внутри блоков. Скриншоты обновлены после функциональных изменений.

`node_modules/` нужен для локального запуска, `dist/` создаётся сборкой, `test-results/` — тестами. Эти каталоги исключены из Git и могут быть восстановлены командами npm. Скриншоты и тесты оставлены как материалы лабораторной.

## Ограничения и следующие этапы

Это frontend-прототип. Посещения, платежи, графики и сотрудники демонстрационные. Авторизация, реальные оплаты и документы не реализованы. Матрица ролей показывает предполагаемые права, но не защищает данные. Локальное хранилище привязано к браузеру и адресу сайта, не заменяет базу данных и не синхронизирует параллельную работу в нескольких вкладках или устройствах.

Следующие крупные задачи: Python + FastAPI API, PostgreSQL + SQLAlchemy, серверная валидация и авторизация, затем реальные расписание, посещения и абонементы. Тема и платформа Git-репозитория согласуются с преподавателем; перед сдачей нужен доступ преподавателю и регулярная история коммитов.

При доработке использовалась ИИ-помощь. Методичка запрещает ИИ-генерацию кода; соответствие этому организационному условию не заявляется. Памятка [для защиты](docs/defense.md) помогает разобраться в реализации, а не скрывать происхождение кода.
