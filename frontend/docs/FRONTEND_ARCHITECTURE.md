# FlowBiz frontend architecture

## Стек и сохранённая основа

React 18, TypeScript, Vite, React Router, Tailwind CSS 4, существующие Radix UI/Lucide/Recharts dependencies. Новые пакеты не добавлялись. Исторические экраны MyBusiness остаются в репозитории как исходный код, но корневой React application теперь использует новый пользовательский сценарий.

## Страницы и маршруты

| Маршрут | Назначение |
|---|---|
| `/register` | короткая регистрация |
| `/onboarding` | категория и описание бизнеса |
| `/configure` | редактирование mock-предложения |
| `/ready` | подтверждение созданного пространства |
| `/` | обзор бизнеса и задачи на сегодня |
| `/clients`, `/clients/:id` | список и универсальная карточка клиента |
| `/schedule`, `/groups`, `/team`, `/payments`, `/documents`, `/tasks` | операционные списки |
| `/automations`, `/reports`, `/settings` | правила, аналитика и настройка |

Существующий React Router сохранён. До появления рабочего пространства пользователь направляется на регистрацию; после создания workspace недопустимые onboarding-пути возвращают на главную. Ссылки меню формируются из включённых сущностей конфигурации.

## Данные и поток

`src/app/product/model.ts` содержит универсальные типы бизнес-категории, сущности, поля, процессы, автоматизации, setup и операционных записей. `catalog.ts` предоставляет шаблоны для восьми категорий. `mockWorkspaceService.ts` изолирует localStorage и начальные записи; `workspaceApi.ts` содержит типизированные вызовы FastAPI. UI-слой обращается к `workspace-context.tsx`, где сосредоточены состояние setup/data, переключение режимов и команды интерфейса.

```text
React pages/components → Workspace context → workspaceApi → FastAPI → PostgreSQL
                                      ↘ mockWorkspaceService → localStorage (offline/demo)
```

Компоненты не обращаются напрямую к таблицам/схеме БД. Сейчас API сохраняет организацию и версию конфигурации, читает/создаёт клиентов и вычисляет dashboard summary. Остальные разделы используют локальные mock fixtures. При недоступном сервере приложение явно сообщает, что работает локально.

## Компонентные паттерны

- Shell, sidebar и topbar: рабочая навигация с мобильным drawer.
- PageHeading, Metric, StatusBadge: повторяемые заголовки, показатели и статусы.
- ConfigList/ConfigItem: элементы предлагаемой структуры с включением и переименованием.
- Panel/table/search: списки универсальных сущностей.
- Client detail: контакты, заметка и activity timeline как пример универсальной страницы записи.
- Modal: создание клиента; quick actions и responsive controls для узкого экрана.

## Состояние и ограничения

`WorkspaceProvider` хранит черновик регистрации, настройку и состояние экрана. В localStorage сохраняется локальная копия workspace для восстановления. При подключённом API создание организации и конфигурации, загрузка/добавление клиента и dashboard summary идут через `workspaceApi`. Команды задач и автоматизаций пока работают локально. API не является авторизацией: пароль не сохраняется и запросы пока не привязаны к сессии пользователя. Оплаты, отчёты, расписание и документы используют демонстрационные данные; загрузки файлов нет.

## Адаптивность

Основной макет рассчитан на desktop; при ширине планшета sidebar становится drawer, сетки переходят на одну колонку, таблицы сохраняют горизонтальную прокрутку. На мобильном экране действия, поля и карточки доступны без hover.

## Подключённые API контракты

- `POST /organizations` — зарегистрировать организацию с категорией бизнеса.
- `PUT/GET /organizations/{id}/workspace` — сохранить и загрузить конфигурацию с номером версии.
- `GET/POST/PATCH/DELETE /organizations/{id}/clients` — клиентские записи и поиск.
- `GET /organizations/{id}/dashboard-summary` — серверные агрегаты по статусам клиентов.

Дальнейшие API: аутентификация и сессии, роли, расписание, задачи, платежи, документы, уведомления, аудит и внешние интеграции.

Для всех мутаций UI следует добавить pending/error состояния, валидацию, optimistic update только при безопасном откате и повторную загрузку после конфликтов версии.
